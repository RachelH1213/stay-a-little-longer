## 1. 画面

### 1.1 现在是什么样

我看了 `07-held-glow.png`（1280 × 720，拿着手机）：

- 手机在正中，占了画面高度的 94%，左右各空出大约三分之一的宽度。
- 房间在后面，被一层深色盖着（`--scrim`，0.78），只看得出窗、台灯和桌面的轮廓。
- 整个界面是同一个 UI 面板，面板的单位就是手机的单位：手机屏幕永远是 280 × 512 个单位。所以**放在手机外面的东西，用的是和手机里一样的单位、一样的字号**，不需要另外算缩放。

16:9 的画面大约是 1060 × 596 个单位：

```text
0            370        690           1060
|-- 左边 370 --|-- 手机 320 --|-- 右边 370 --|
```

16:10（MacBook）每边大约 316 个单位。一张最宽的卡片（内容 280，加纸边 292）两种比例都放得下。

### 1.2 分层

从后到前：

| 层 | 内容 |
|---|---|
| 1 | 房间 |
| 2 | 那层深色（不变） |
| 3 | 手机 |
| 4 | **桌面层（新）：** 卡片、笔记本那一页 |
| 5 | 正在拖的那一块 |
| 6 | 暂停菜单、夜晚开头结尾的黑幕（不变） |

- 卡片在深色那一层的上面，所以**卡片和笔记本一直是正常亮度**，后面的房间是暗的。这正是你要的：不用把卡片弄暗，也不用另外做什么让它显眼。
- 卡片在手机的上面，所以可以盖住手机的一部分。
- 手机里的弹层（Forward、`Accepted for you.` 那些）还在手机里面，不受影响。

### 1.3 默认放在哪

| 东西 | 第一次出现的位置（单位） |
|---|---|
| 笔记本那一页 | 右边一栏：左边离手机 16，上边离画面顶 24，宽 240 |
| 用菜单拿出来的卡片 | 左边一栏：右边离手机 16，从上边 24 开始往下排，每张之间隔 8。排满了，后面的每张比前一张往右下错开 12。 |
| 用拖拿出来的卡片 | 松手的地方 |

之后都按玩家摆的来。位置存进存档。

## 2. 什么能拿出来

一块东西能不能拿，由它是什么决定。一共八种：

| 种类 | 手机里的哪一块 | 卡片下面那行小字 | 现在代码里画它的地方 |
|---|---|---|---|
| `message` | 一条消息；同一个人连着发的几条算一组，拖其中任何一条，拿出来的是整组（最多 8 条） | `Rachel · 11:56 PM` | `Message()` |
| `plan` | 计划详情最上面那张卡 | `Plan · 11:38 PM` | `RenderPlanDetails()` |
| `record` | History 里的一条记录；点开的弹层（`Accepted for you.`）也算 | `Plan · History · 11:40 PM` | `RenderPlanHistory()`、`TimelineEntry()` |
| `profile` | 主页上头像以下到 `Send a message` 为止的一段 | `Rachel's profile · 11:53 PM` | `RenderProfile()`、`ProfileHead()` |
| `setting` | Orbit 设置里的一行，连同它下面的说明 | `Orbit settings · 11:45 PM` | `RowsCard()`、`FieldRow()` |
| `notification` | 锁屏上或者横幅上的一条 | `Notification · 11:56 PM` | `RenderLock()`、`ShowBanner()` |
| `note` | Notes 里的一条旧笔记 | `Notes · 11:34 PM` | `RenderNote()` |
| `sheet` | 手机里任何一个说明性的弹层（比如点 `[hidden]` 出来的 Contact Protection） | `Orbit · 11:49 PM` | `ShowSheet()` |

- 小字里的时间是**拿出来的时刻**（故事里的时间），不是那条消息本身的时间。消息自己的时间在卡片里面，照原样画。
- **拿不出来的：** 整页、状态栏、输入框和键盘、建议回复那一排、底下的标签栏、手机自己的 Settings。
- 12:40 之后她的对话变成 `Orbit User`：屏幕上是什么，拿出来就是什么。之前拿的那张不变。
- 第二、三晚新增的东西（`Keep talking` 那张卡、Orbit 替玩家写的回复）到时各加一种，做法一样。

## 3. 拿出来

### 3.1 用拖

| 步 | 玩家做什么 | 发生什么 |
|---|---|---|
| 1 | 鼠标移到一块能拿的东西上 | 指针变成张开的手。（移到按钮上还是现在的手指。两者重合时，比如一条能点开的记录，用张开的手。） |
| 2 | 按下 | 那一块显示按下的样子（已有）。 |
| 3 | 移动。横向超过 10 个单位，并且横向比纵向多 | **抬起：** 一份一样的东西出现在鼠标下面，比原位高 2 个单位，带影子；原位留一个淡的轮廓；指针变成握住的手。0.08 秒。 |
| 3′ | 移动是纵向的 | 不抬起。原来的意思不变（主页下拉刷新、状态栏下拉）。 |
| 3″ | 没移动，松开 | 就是一次点击，原来点它会发生什么，照旧发生。 |
| 3‴ | 没移动，按住半秒 | 出菜单（见 3.2）。 |
| 4 | 拖着走 | 那一份跟着鼠标，不被手机的边裁掉。鼠标一离开手机屏幕的范围，它换成卡片的样子（纸边、胶带、下面那行小字）；回到屏幕里，换回去。 |
| 5a | 在屏幕外松手 | 它留在那里，成为一张卡片。原位的轮廓填回去。一声很轻的纸声。 |
| 5b | 在屏幕里松手，或者按 Esc | 它滑回原位，0.15 秒。什么都没发生，不记录，不花时间。 |

- 10 个单位就是现在代码里取消长按的那个距离（`RegisterLongPress`），所以「动了是拖，没动是菜单」正好接上。
- 抬起之后的那一次松手不算点击。不然拖完一条 Rachel 的消息，Forward 菜单会跳出来。
- Reduce motion 开着：第 3 步没有动画，5b 直接回去。

### 3.2 用菜单

| 东西 | 怎么打开菜单 | 菜单里有什么 |
|---|---|---|
| Rachel 的消息 | 点它旁边的 `···`，或者点它，或者按住半秒（都是现在已有的） | `Forward ›`、`Screenshot`、`Cancel` |
| 别的能拿的东西 | 按住半秒，或者鼠标右键 | `Screenshot`、`Cancel` |

点 `Screenshot`：菜单关掉，那一块自己抬起来，越过手机的边，落到 1.3 说的位置上，0.3 秒。Reduce motion 开着时直接出现在那里。

### 3.3 花费和限制

| | 规则 |
|---|---|
| 花费 | 不花时间，不花电。（现在第一次截图花 1 分钟：`if (State.photos.Count == 1) Spend(1, 0)`。去掉。） |
| Battery Saver 开着 | Orbit 里的东西拿不出来：指针不变成手，拖不起来，菜单里的 `Screenshot` 是灰的，下面一行 `Screenshots of Orbit are paused.`（已有的字）。Notes 和锁屏通知照常能拿。桌上已有的卡片不受影响。 |
| 同一块东西拿两次 | 可以。两张卡片，各自定格在各自的时刻。这有用：刷新前后的主页各一张。 |
| 手机没电、夜晚结束 | 拿不了。 |

### 3.4 游戏记下什么

每拿一次：

- 行动记录里一条：`screenshot`，是哪一种，是哪一块（`LogAction("screenshot", kind, sourceId)`）。
- 事件：沿用现在的 `N1_EVIDENCE.screenshot.<id>`；拿的是 MSG_1048 时，沿用 `N1_FIRST_FAKE.saved`（`saved_msg_1048`）。后面依赖这两个的规则不用改。

## 4. 卡片

### 4.1 长什么样（单位）

```text
┌──────────────────────────────┐
│          ▭ 胶带           ×  │  上边 14
│ ┌──────────────────────────┐ │
│ │                          │ │
│ │   那一块东西，和手机里   │ │  内容：底色和手机屏幕一样，四周留 8
│ │   画得一模一样           │ │
│ │                          │ │
│ └──────────────────────────┘ │
│ Rachel · 11:56 PM          ◢ │  下边 18
└──────────────────────────────┘
  纸边 6
```

| 部分 | 规格 |
|---|---|
| 纸 | `--paper`（`#E7DAB9`，和提袋里那张纸条同一个颜色） |
| 内容 | 底色 `--bg`，和手机屏幕一样。里面用手机的七种字、手机的颜色，一个字都不另设。 |
| 小字 | Secondary（11），颜色 `--ink`，只占一行，放不下时末尾用 `…` |
| × | 画出来 12，能点的范围 24 |
| 右下角的角 | 画出来 12，能拖的范围 20 |
| 影子 | 往右下 2，黑色，不透明度 0.5，硬边（像素风格，不要模糊的影子） |

### 4.2 能做的事

| 动作 | 怎么做 | 细节 |
|---|---|---|
| 挪 | 按住卡片上除了 × 和角以外的任何地方，拖 | 松手就放下。位置落在整数单位上。整张卡片不能出画面：拖到边就停。 |
| 到最上面 | 点它，或者开始拖它 | |
| 调大小 | 拖右下角 | 见 4.3 |
| 关 | 点 × | 从桌上消失。它还在 Photos 里。 |
| 发给人 | 拖到对话的输入那一行上松手 | 见第 5 节 |
| 夹进笔记本 | 拖到笔记本的某个问题上松手 | 见 6.6 |

### 4.3 大小

- 拖右下角改的是**内容区的宽度**，在 120 到 280 之间，一个单位一个单位地变。
- 里面的字按新的宽度重新换行。字号不变。
- 高度跟着内容走。可以再往上拖，把下面裁掉：最短留两行内容，最后一行以 `…` 结尾。往下拖过了内容的底就停住。
- 双击那个角：回到 280 宽，高度回到完整。
- **不重排的：** 她自己打的换行（那张便条永远是三行）；一组消息各是各的气泡；头像和图片不缩放；左标签右数值的一行，窄到放不下时数值掉到标签下面；`Accepted for you.`、`[hidden]`、时间这类短词不在中间断开。

**怎么保证不糊。** 面板的单位对桌面层和手机是同一个，所以卡片里的字和手机里的字是同一个字号、同一种画法。现在代码里有一步把 VT323 的字挪到整像素上（`SnapPixelText()`），只扫手机屏幕里面；让它把桌面层也扫一遍。头像的整数倍缩放（`FitAvatar`）同理。

### 4.4 数量

- 桌上同时最多 8 张（不算笔记本）。拿第 9 张时，最早放上去的那张自己关掉（回 Photos）。
- Photos 里不设上限。一张卡片存的只是几行字，不是图片文件。

### 4.5 放下手机、睡觉、继续

| 情况 | 卡片 |
|---|---|
| 放下手机（Esc） | 都收起来，房间里只有房间 |
| 再拿起来 | 回到原来的位置、大小、叠放顺序 |
| 手机没电 | 和放下一样。充上电拿起来，都回来。 |
| 退出游戏再 Continue | 同上，一模一样 |
| 这一晚结束 | 桌上的卡片全部关掉（回 Photos）。夹在笔记本里的留在笔记本里。下一晚桌上是空的，Photos 和笔记本里的都还在。 |

### 4.6 Photos 里

Photos 页面不用大改：

| | 现在 | 改成 |
|---|---|---|
| 格子里的每一张 | 整屏截图的缩小图 | 那一块东西的左上角，按原大小裁成方的（不缩小，所以不糊） |
| 点开一张 | 整屏截图，外面一圈线，下面是时间和来源，右上 `SHARE` | 那一块东西，同样一圈线，同样的小字，同样的 `SHARE` |
| 点开的那一张 | — | 也能拿出来（拖，或者按住出菜单里的 `Put on desk`）。已经在桌上的，菜单里这一项是灰的。 |
| 删除 | 没有 | 点开后菜单里 `Delete`。桌上和笔记本里的那一张一起没有。 |

`Put on desk` 和 `Delete` 是新的字，要你定。

## 5. 把卡片给人看

### 5.1 怎么给

1. 开着 Juno 或 Dani 的对话。
2. 抓起一张卡片，移到手机屏幕最下面输入的那一行上（输入框和它上面的建议回复）。那一行亮起一圈 Orbit 的环。
3. 松手。卡片作为一条消息发出去，在对话里画成那一块东西（宽度是气泡的宽度，同样重新换行）。桌上那张回到它被抓起之前的位置。

- **只有输入那一行是「发出去」。** 卡片可以盖住手机，所以松在手机的别处只是放在那里。
- 花费和发一条消息一样：1 分钟，0.5%。
- 开着的不是对话，或者 Juno 关着、Snooze 着：那一行不亮，松手只是放下。
- **不拖的路：** Photos → 点开 → `SHARE` → 选人（已有）；计划上的 `Share`（已有）；消息的 `Forward`（已有）。

### 5.2 对方怎么反应

**这一轮不写任何新台词。** 现在的 `SharePhoto()` 已经按截图里是什么分了几种情况，卡片直接对上去：

| 卡片 | 给 Juno | 给 Dani |
|---|---|---|
| MSG_1048 那一组（`message`） | Juno 已经拿到那条消息：`JunoSeenIt`。还没拿到：`JunoOnFakeScreenshot`（`it's a screenshot…` · `forward me the message?`），并等玩家答复。和现在一样。 | `DaniSeesMsg1048()`，和现在一样 |
| 刷新之后、消失之前的主页（`profile`） | `JunoOnLastActive`，和现在一样 | 现在没有反应 |
| 计划（`plan`） | 走 `SharePlan("juno")`，和点 `Share` 一样 | 走 `SharePlan("dani")` |
| 别的 | `JunoOnOtherScreenshot`，和现在一样 | 现在没有反应 |

- 「现在没有反应」的那几格，等九层那一轮和「指出哪里」那一轮的台词（`night1-layers.md` 里 Dani 的反应、我那份 `pointing-and-notes` 草稿）。卡片先做出来不会挡住它们：到时只是在这张表里填格子。
- 转发带来源、图不带来源的规则不变：把 MSG_1048 的卡片给 Juno，它仍然要你转发。

### 5.3 给 Rachel

把卡片拖到 Rachel 的输入那一行：我建议**可以发**，和玩家给她打字一样处理（现在的 `playerContactedRachel` 那一套），没有任何特别的反应。12:40 之后和打字一样发不出去。

理由：玩家很自然会想把 `You accepted` 那条记录发给她看。不让发，是一堵没有道理的墙。要你定。

### 5.4 第二、三晚

`revision-2026-11.md` §3.5 已定：Messages 能发图，截图是把 Orbit 屏幕上的东西带出 Orbit 的唯一办法。卡片就是那个截图：拖到 Messages 的输入那一行，或者在 Messages 里选图。这一轮不做，但第 7 节的数据是按这个留好的。

## 6. 笔记本

### 6.1 房间里的那一本

- 房间里加一个可以点的东西：`Notebook`。和提袋、台灯一样的做法（`room-hotspots` 里加一个 `room-notebook`，`Night1RoomView.RoomObject` 加一项，范围从美术图上量）。鼠标移上去：四个像素角标和它的名字，和别的东西一样。
- **拿着手机时，房间里别的东西仍然点不了，只有它可以。** 它在深色那一层下面，是暗的；鼠标移上去时角标和名字照常出现，所以找得到。

### 6.2 两种打开的方式

| 情况 | 点笔记本 | 再点一次，或者点 × |
|---|---|---|
| 手机放在桌上 | 那一页在画面中间放大（和提袋里的纸条一样，后面的房间暗下去）。可以滚、可以点书签。点页面外面关掉。 | 关掉 |
| 拿着手机 | 那一页作为一张卡片开在桌面层上。可以挪、调大小、关，和别的卡片一样。 | 关掉 |

- **这一晚第一次拿起手机时，它已经开着**（位置见 1.3）。之后按玩家留下的状态。
- 它不算进 8 张的上限。
- 它的大小：内容区宽 160 到 320，高最多 480；内容比它长时用滚轮在里面滚。

### 6.3 这一页上有什么

```text
 tue                                    ← 书签。第一晚只有一个。
┌────────────────────────────────────┐
│ Tuesday night                    × │
│                                    │
│ w̶h̶y̶ ̶d̶i̶d̶n̶'̶t̶ ̶s̶h̶e̶ ̶c̶o̶m̶e̶          ▢  │  ← 划掉的问题。▢ 是夹在这里的一张卡片
│    she moved it herself, 5:12.     │  ← 答案行，缩进
│    it says i accepted       11:40  │
│                                    │
│ who said yes                       │  ← 还开着的问题
│ her email?                         │
│                                    │
│ ─────                              │
│ 11:31  she didn't come.            │  ← 不属于任何问题的事
│ 12:02  her note is still in the bag│
│                                  ◢ │
└────────────────────────────────────┘
```

从上到下三段：

1. **问题。** 顶格写。解开的划掉，解开它的那件事缩进写在下面，右边是时间。
2. 一道短线。
3. **别的事。** 按时间排，每行前面是时间。

**字从哪来。** 分两步，这样笔记本可以先做出来，不用等别的：

| 阶段 | 问题那一段 | 别的事那一段 |
|---|---|---|
| 先做（接现有的代码） | 现在 `Tuesday night` 那条笔记里 `Still unresolved` 下面的那些行（`StillUnresolved()`）。现在一条解决了就从列表里消失；改成留在纸上、被划掉。 | 现在那条笔记里带时间的那些行（`NightLogEntries()`），字不变 |
| 「指出哪里」那一轮 | 换成我那份草稿第 12 节的十个问题和它们的答案行（如果你采纳那一份） | 不变 |

**手机里的 Notes：** `Tuesday night` 那一条从列表里去掉。`crit` 和 `first time, finally` 两条旧笔记不动。

### 6.4 写和划

| 发生了什么 | 这一页开着 | 这一页关着，或者手机放下了 |
|---|---|---|
| 多了一行（问题、答案、别的事） | 那一行从左到右写出来，0.4 秒，写字的声音 | 写字的声音；下次打开时它已经在那里 |
| 一个问题解开了 | 一道线从左到右划过那一行，0.35 秒，笔尖的声音；然后答案行写出来 | 笔尖的声音；下次打开时已经划掉 |
| 一行被改写（见 6.5） | 两道短促的线划掉旧的（各 0.15 秒），新的写在下面 | 同上，只有声音 |

- 关着的时候除了声音，房间里那本笔记本的角标亮一秒。那是房间自己表示「这样东西」的方式，不是新的提示。
- 问题折成两行时，划线是两道，先上后下。
- Reduce motion 开着：没有写和划的动画，字和线直接出现。声音照常。
- 现在 Unity 里还没有任何声音。这里要三个：写字、划线、放下卡片的纸声。可以先用占位的。

### 6.5 改写

今晚只有两处：

| 什么时候 | 旧的一行（划掉） | 新的一行（写在下面） | 出处 |
|---|---|---|---|
| 玩家对 Juno 或 Dani 说出了怀疑 | `She wrote back. 11:37 PM.` | `A message came from her account at 11:37 PM.` | `revision-2026-11.md` §2.7，已定。现在是一行字悄悄换掉；改成看得见。 |
| 看到 `Accepted for you.` | 第一个问题答案里的 `it says i accepted` | （不另写。下一个问题的答案行就是 `accepted "for me"`。） | 我的建议，随十个问题那一轮一起定 |

第一处的时间 `11:37` 是文档里的例子，实际是假消息到的时刻。

### 6.6 把卡片夹在问题旁边

- 抓着一张卡片移到笔记本的某个问题上（开着的或者划掉的都行），那一行下面出现一道虚线。松手。
- 那张卡片从桌上消失，在那一行的右边变成一个小方块：一个表示种类的小图标（消息、计划、记录、主页、设置、通知、笔记、弹层，八个）。不是把卡片缩小画一遍，缩小的字会糊。
- 鼠标移到小方块上：显示那张卡片的小字（`Rachel · 11:56 PM`）。点它：卡片回到桌上原来的位置和大小，小方块留着（表示它属于这里）。
- 一个问题旁边最多显示 3 个小方块，更多的写成 `+2`，点了展开。
- 拿走：把小方块拖出笔记本的边。
- **不验证。** 夹在哪里没有对错，游戏不因为它发生任何事。

### 6.7 一晚一页（第二晚起）

这一轮只留位置，不做内容：

- 新的一晚第一次打开时，上一晚没划掉的问题由笔抄到新一页最上面，在一行小字 `still open` 下面。
- 第二晚早上哪些问题会当场划掉，要对着 `night2-scenes.md` 定。

## 7. 存什么

卡片不存成图片。存的是**画出那一块所需要的字**，画的时候用和手机里同一套画法。这样：存档只是文字；改了 Text Size 卡片跟着变；Continue 之后一模一样。

在现有的 `Night1Photo` 上加字段（`State.photos` 这个列表接着用，`SharePhoto()`、Photos 页面都不用换数据）：

| 字段 | 内容 |
|---|---|
| `id`、`storyMinutes` | 已有 |
| `kind` | 第 2 节的八种之一 |
| `sourceId` | 是哪一块：消息的 id、计划的 id、记录的 id、设置那一行的名字… |
| `caption` | 下面那行小字，拿的时候就写好 |
| `fields` | 一串「名字、值」。画这一块需要的每一个字：发的人、每条消息的正文和时间、计划的名称时间地点状态、记录的文字和有没有那个环、主页的 `Last active` 那一行… **拿的时候抄下来，之后不再读游戏的状态。** |
| `showsFake`、`showsRefreshedProfile` | 已有。拿的时候按 `kind` 和 `sourceId` 算出来，`SharePhoto()` 照旧读它们。 |
| `onDesk`、`x`、`y`、`width`、`height`、`order` | 在不在桌上；位置；内容区的宽；裁短后的高（0 表示完整）；叠放顺序 |
| `tuckedTo` | 夹在笔记本的哪个问题旁边；空的表示没夹 |
| `file`、`screen` | 已有，只有旧存档里的整屏截图在用 |

笔记本另存：

| 字段 | 内容 |
|---|---|
| `notebookOpen`、`notebookX`、`notebookY`、`notebookWidth`、`notebookHeight` | 开没开，位置和大小 |
| `notebookLines` | 一串行。每行：`id`、哪一晚、是问题、答案还是别的事、文字、属于哪个问题、几点写的、几点划的（没划是 -1）、是解开还是改写。**只增不减**，划掉也是在那一行上记一笔。 |

- 存档版本从 6 升到 7。旧存档里的整屏截图照旧显示在 Photos 和已经发出去的消息里，只是不能再拍新的。
- `fields` 用一串「名字、值」而不是字典：Unity 存档用的 `JsonUtility` 存不了字典。

## 8. Unity 里怎么接

这一节是给写 Unity 提示的人看的。结构是建议，做的人可以换，只要第 9 节的验收过得去。

### 8.1 新的和要动的

| 文件 | 做什么 |
|---|---|
| `Night1Engine.Photos.cs` | `TakeScreenshot(file, fakeInView)` 换成 `TakeBlock(kind, sourceId, fields)`：建一条 `Night1Photo`，算两个 `shows…`，记事件，不花时间。加 `PlaceOnDesk`、`MoveCard`、`ResizeCard`、`CloseCard`、`TuckCard`、`UntuckCard`、`DeletePhoto`。`SharePhoto()` 不动；加一个入口，`kind` 是 `plan` 时转到 `SharePlan()`。 |
| `Night1Engine.Notebook.cs`（新） | `WriteLine()`、`StrikeLine()`、`ReviseLine()`。现在往 Night Log 加一行的地方、`StillUnresolved()` 里一条出现和消失的地方，改成调这三个。 |

| `Night1PhoneFocusView.cs` | 画每一块时登记它「能拿」（一个类名 `phone-pullable`，带上 `kind`、`sourceId` 和 `fields`）；菜单里加 `Screenshot`；快捷面板去掉 `Screenshot` 那一格；Photos 的格子和详情改用 `Night1BlockView`。 |

### 8.2 三处容易出错的

1. **点击和拖是同一次按下。** 一条 Rachel 的消息现在点一下就出 Forward 菜单（`ClickEvent`）。拖起来之后的那次松手不能再触发它。
2. **手机每次重画会把屏幕里的东西换成新的。** 拖到一半时如果来了新消息、屏幕重画，被拖的那一份不能跟着没了。所以被拖的那一份从一开始就是桌面层里另建的一个，不是把手机里的那个元素搬出来。
3. **定格。** 卡片画的时候只能读它自己的 `fields`。一个容易犯的错是画计划卡时顺手读了 `Plan.status`，那样玩家拒绝改期之后，桌上那张旧卡片也跟着变了。测试里专门有一条查这个（第 9 节）。

## 14. 我没把握的

1. **横向 10 个单位会不会太容易误触。** 点消息时手一抖就会抬起来。没有后果，但可能要调到 14 或 16。第一轮做完要你亲手试。
2. **把画法抽成 `Night1BlockView` 有多大。** `Night1PhoneFocusView.cs` 现在 2784 行，八种东西的画法散在里面，有的还直接读游戏状态。这是第一轮里最大的一块，也是最值得做的一块：不抽出来，卡片和手机迟早画得不一样。
3. **拿着手机时点得到房间里的笔记本吗。** 手机那一层现在盖住整个画面。要让那一层在手机以外的地方不拦鼠标，同时卡片照常能点。道理上可以，我没法在这里跑 Unity 验证。
4. **16:10 以外更窄的窗口。** 每边不到 300 个单位时，最宽的卡片会盖住手机的边。可以盖是定了的，所以不算错，但要看一眼是不是难用。
5. **以后的 iOS 版没有桌面。** 到时卡片只在 Photos 和笔记本里，不能并排。这是那个版本的损失，现在不用管，但第 7 节的数据不需要为它改。
